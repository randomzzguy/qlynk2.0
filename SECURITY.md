# Security policy

Report suspected vulnerabilities privately to **info@qlynk.site**. Include the affected version, a minimal reproduction and potential impact. Do not send passwords, secret keys, private customer documents or raw visitor conversations.

Please do not open a public issue containing an exploitable vulnerability or sensitive data. Test only deployments you control or have explicit authorization to assess. We will review reports; this project does not promise a paid bounty or a fixed response deadline.

Self-hosting operators are responsible for updates, provider credentials, HTTPS, database row-level security, backups, access controls and compliance with their own use case. Apply migrations as well as application updates; client UI controls alone are not an authorization boundary.
